# LG 长篇小说创作 Agent 优化方案：让人物与关系获得生长的历史

> 修订时间：2026-07-18
>
> 前提：轻流程、Full Agent、廉价 API、官网强模型接力、本地保存全部作品记忆
>
> 核心目标：不是制造“灵性段落”，而是不把长篇历史压扁，让人物、关系和世界保有产生意外而成立之事的可能

> 目标架构与代码迁移方案见：[LG Living History Agent 目标架构](./living-history-agent-architecture.md)

## 0. 先撤回此前错误的方向

此前方案仍然把“灵性”处理成了工程对象：寻找火种、标记火种、保存火种、保护火种，再把它传播到后续情节。

这条路的问题不只是命名不好，而是对象找错了。

灵性不是一段可以从正文中摘出的特殊文本，也不是一种能被用户点击、模型评分、数据库保存的品质。把它做成 `Spirit Engine`、`Spirit Kernel` 或“火种档案”，最终都会诱导系统生产看起来重要的句子、意象和选择。那仍然是 AI 最擅长的模式模仿。

本方案明确删除以下设计：

- 不建立 Spirit Engine、灵性评分器或火种工作流；
- 不要求用户标记“这里有灵性”；
- 不从微改、保留、继续阅读等行为推断审美；
- 不把人物写成可预测的性格模型；
- 不寻找跨作品、跨人物的“灵性规律”；
- 不规定关键场景必须读取哪些原文、生成几个候选或走几步流程；
- 不让固定 Context Compiler 配方替 Agent 决定应该知道什么。

价值层级仍然成立：

> 不可替代的生命感 > 世界生命与人物因果 > 技巧与审美 > 表面表达。

但第一项不是可优化指标。产品能做的，是避免破坏它可能出现的条件。

## 1. “故人将去”真正说明了什么

第 452 章中，巴东王临死前要求见王扬。按照常见写法，这里很容易进入忏悔、和解、交心、悲壮告别或体面赴死。

实际发生的却是：巴东王反复设法偷袭王扬，王扬一边防着他，一边仍以故人之礼相待。最后两人的对话既滑稽、危险，又带着只有他们之间才可能存在的情感。

这段成立，不是因为作者写出了一句漂亮的话，而是因为：

- 巴东王到将死时仍然没有被主题净化；
- 王扬理解他，却没有因为理解而取消警惕；
- 敌意、信任、虚荣、敬意、孩子气和死亡同时存在；
- 人物没有为了“感人”而停止做自己；
- 这一行动在发生前无法从性格标签推导，发生后却能在四百多章历史中找到根；
- 新情节不只是证明巴东王原来是什么人，而是再次塑造了巴东王是谁；
- 读者不是获得一个人物结论，而是更确定地感觉到这个人存在，同时更难概括他。

可以在事情发生以后这样描述：

> 事前不可算，事后处处有根；人物因此更具体，却没有因此更容易被总结。

这不是生成公式。若把它反过来写进提示词，让模型“生成一个意外但合理、能够塑造人物的行动”，模型只会模仿惊奇、反转和高级感。

真正重要的是前四百多章没有把巴东王耗尽。

## 2. 新的核心目标：不是理解人物，而是让人物拥有未被解释完的过去

### 2.1 人物不是状态向量

人物卡可以写“骄傲、暴烈、重情”，但这些词无法生成狱中那场戏。它们只会让模型反复证明人物骄傲、暴烈、重情，最终把人物写成自己的标签。

人物真正由以下东西构成：

- 他实际做过的具体事情；
- 他对同一件事在不同时期的不同反应；
- 他记住、忘掉和误解的东西；
- 他对不同的人展现出的不同自己；
- 他曾经说过却没有做到的事；
- 他自己也无法统一的矛盾；
- 生活在他身上留下、但尚未获得意义的细节；
- 后来的行动对过去造成的重新解释。

因此，写得越久，人物不应越容易预测。读者会越来越认识他，却仍然无法计算他下一步具体会做什么。

### 2.2 关系不是好感度

关系也不是“敌对 40、信任 65、惺惺相惜”之类的状态。

同一段共同历史，在双方心中并不相同。王扬可能记住危险，巴东王可能记住终于有人理解自己。每个人携带的是自己的关系版本。

长期关系还会产生一种只存在于两人之间的生命：

- 某个人只在另一个人面前出现的一面；
- 只有彼此听得懂的旧话、挑衅和礼节；
- 没有偿清的亏欠与没有兑现的承诺；
- 一方以为已经过去、另一方却仍在承受的事情；
- 即使立场改变也不会自动消失的相处方式。

第 452 章不是两个独立人物各自执行性格，而是他们之间积累了数百章的关系再次行动。

### 2.3 铺垫不是提前公布答案

好的铺垫使行动在发生后有根，却不能让读者在发生前算出答案。

如果前文明确写过“巴东王有仇必报，临死也必须打对手一下”，狱中偷袭便只是伏笔回收。真正有效的前文提供的是人格材料、共同历史和未完成的张力，而不是未来行为说明书。

所以系统不应只维护“待回收伏笔”。它还要允许大量当下没有明确用途的生活、动作、误解和关系细节存在。未来可以重新赋予它们意义，但写下它们时不必知道用途。

### 2.4 人物可以推翻大纲

大纲适合保存外部压力：谁将死、战争何时到来、制度造成什么困境、哪些资源正在耗尽。

大纲不应过早规定人物必须如何反应。若人物与关系已经生长到不会执行预定情节，Agent 应允许他们改变大纲，而不是把人物拽回作者最初安排的主题动作。

## 3. “规律就是没有规律”在产品中的含义

这里的“没有规律”不是随机，也不是拒绝一切工程。

它意味着：不存在一套从人物特征到具体行动的稳定映射，也不存在一种跨作品复用的高级人物模板。

系统可以维护事实、历史、来源、时间和检索能力，却不能预先规定这些历史最终应长出什么。它可以减少以下失败：

- 人物为推进剧情突然行动；
- 人物不断复读自己的标签；
- 关系变化只表现为亲密度升降；
- 冲突被主题句或和解迅速封闭；
- 关键时刻自动进入悲壮、治愈或升华；
- 新情节只回收一个显眼伏笔；
- 后文忘记旧事，人物像每章重新加载；
- 摘要取代原作，模型只和人物简介互动。

但系统不能据此保证高级创作。它只能让模型面对一个没有被整理成答案的、足够具体的过去。

## 4. 产品形态：一个 Full Agent，而不是一组创作机关

### 4.1 用户表面只有极轻循环

```text
用户：继续
  -> Agent 自行判断需要读什么、想多久、调用哪个模型
  -> 直接写入作品并维护本地记忆
  -> 用户阅读

用户：这里不对，因为……
  -> Agent 判断是当前动作错误，还是人物已连续写偏
  -> 自行追溯相关历史、修改正文与必要的后续安排
  -> 保留用户原话作为本作品的纠正证据
```

用户不需要：

- 选择权限；
- 审批文件写入；
- 维护人物数据库；
- 标记灵性；
- 训练审美模型；
- 每章选择三个方向；
- 理解摘要、索引、compaction 或 handoff。

### 4.2 Full 权限与 Agent 自主判断

Agent 在作品工作区内始终拥有完整读写权限。版本、ledger 和回滚负责恢复，不把安全感建立在用户审批上。

同样，产品不替 Agent 硬编码：

- 本章必须读取几段原文；
- 原文一定比摘要更好；
- 关键场景必须生成多个候选；
- 某类任务最多只能检索两层；
- 每次官网接力固定使用某套卡片。

系统提供能力、预算信息和来源，Agent 决定如何使用。

### 4.3 少做专用 Engine

不需要分别建设 Spirit Engine、Relationship Engine、Taste Engine 和一套复杂工作流编排。

真正需要的是较小的基础设施：

1. 可靠的文件读写、搜索、版本和回滚；
2. 能从摘要或索引追到原文的本地记忆；
3. 能感知 Token、成本和上下文余量的 Agent；
4. 可替换的廉价 API 与官网强模型接力；
5. 保留用户明确纠正的项目内记忆；
6. 不把派生摘要误当作品事实的来源规则。

创作判断仍然由 Agent 完成。

## 5. 记忆设计：正文是本体，其他一切都是导航

### 5.1 权威层

作品记忆始终保存在本地。

权威来源包括：

- 正文章节；
- 用户明确写入的设定和大纲；
- 已经发生的客观事件；
- 用户对本作品的明确纠正；
- 文件 revision 与修改历史。

官网模型的对话记忆、模型生成的摘要、人物分析、关系标签和自动评价都不是权威来源。

### 5.2 导航层

为了让廉价模型在长篇中工作，可以维护可重建的导航材料：

- 章节事件索引；
- 人物出现位置；
- 两个人共同出现过的场景；
- 某个物件、旧话、承诺或冲突的来源位置；
- 当前外部压力和时间状态；
- 文件摘要与关键词；
- 最近修改及其 revision。

这些材料的作用是帮助 Agent 找到可能相关的正文，而不是告诉 Agent 人物本质是什么。

导航层可以错、可以过期、可以删除重建。每一条重要记录都应尽量带 `sourcePath`、章节或行号、revision。

### 5.3 不建立唯一人物总结

人物简介可以存在，但必须被视为临时视图，而不是人物本体。

较好的做法不是维护一张不断覆盖旧值的人物卡，而是保留：

- 公开事实；
- 不同阶段的自我理解；
- 不同人物眼中的他；
- 相互冲突的原文证据及来源；
- 当前 Agent 为某次任务生成的临时理解。

临时理解完成任务后可以丢弃。不要把模型这次的解释永久固化成以后所有模型必须服从的人物规则。

### 5.4 关系记忆必须允许不对称

系统可以索引共同场景，但不应强行生成唯一的“关系真相”。

同一事件可以分别记录：

```text
发生了什么：来自正文的客观事件
甲如何理解：只有正文有证据时才记录
乙如何理解：允许与甲完全不同
正文曾从哪个视角呈现：只作原文导航
尚未确定什么：保持未决定
```

系统不维护“读者现在应该知道什么、感受什么”的模型。读者的联想和作品的最终意义不属于项目状态，也不应反过来驱使 Agent 安排暗示、象征和回声。

### 5.5 用户纠正是项目证据，不是审美学习

用户可能说：

- “他不会在这里道歉。”
- “这句话太懂事了，他现在没能力把自己说明白。”
- “不是这一段的问题，前面几章已经把他写软了。”

系统应保存原话、作用对象、当时正文和 revision。它首先用于修复当前作品。

不能从中推出：

- 用户讨厌道歉情节；
- 用户偏爱克制人物；
- 所有角色都不应自我解释；
- 这是一条通用审美规则。

失败版本由版本历史保留即可，不需要每次进入 Prompt。Agent 认为高度相关时再召回。

## 6. Agent 的动态工作方式

### 6.1 “继续”不是固定流水线

一次续写可以大致经历以下判断，但它不是强制工作流：

```text
理解当前任务和写作位置
  -> 查看最小导航信息
  -> Agent 判断现有上下文是否足够
  -> 不足则自行搜索、读摘要、读局部原文或扩大到完整章节
  -> 形成当前局面与压力，而非预设人物答案
  -> 判断本地模型是否足够，或生成官网模型材料
  -> 写出一个实际版本并直接落盘
  -> 更新客观事实、索引和修改历史
  -> 不把本章解释成新的永久人物规则
```

关键是第三步由 Agent 判断。

### 6.2 渐进追溯，而不是固定上下文配方

系统可以提供从便宜到昂贵的访问层：

```text
文件名与章节索引
  -> 简短导航摘要
  -> 命中片段
  -> 相邻场景
  -> 完整章节
  -> 更远的共同历史
```

Agent 可以在任何一层停止，也可以直接跳到原文。产品只显示当前 Token、成本和剩余预算，不规定哪一层才正确。

原文不是宗教。事实查询可能只需索引；关键关系场景可能需要重读多章。让模型根据任务自行决定。

### 6.3 给 Agent 的不是人物答案，而是追问能力

在重要场景前，Agent 可以自行检查：

- 我现在对这个人物的认识是否只剩几个形容词？
- 当前行动是否只是为了完成大纲？
- 是否有某段共同历史可能改变双方对这一刻的理解？
- 两个人记住的是不是同一件事？
- 我是否因为上下文短，误以为某个矛盾已经解决？
- 是否需要回到原文，而不是继续相信摘要？

这些问题只决定要不要继续阅读，不决定人物应该做什么。

### 6.4 大纲以压力为主，以答案为软约束

Agent 读取大纲时应区分：

- 必须成立的外部事实；
- 当前作者设想的方向；
- 尚未发生、可以被人物推翻的具体行动；
- 纯粹为了叙事节奏准备的临时安排。

人物行动若使后续计划不再成立，Agent 可以直接修改软性安排，并保留变更理由和旧版本。

### 6.5 不强制多候选

有时 Agent 会直接写出一个版本；有时它可能在内部尝试多个方向；有时会调用官网强模型寻找突破。

这些都由 Agent 根据难度、成本和当前失败情况决定。不能把“三个正交候选”变成新的仪式，因为固定的多候选同样会生产三种可预测的换皮。

用户默认只看到 Agent 真正选择并写入的版本。

### 6.6 “继续”默认授予创作判断，而不是只续接字面现场

用户只说“继续”时，Agent 可以自行决定沿用当前场景、切换视角、跨越时间或暂时离开主线。它可以写没有明显推进主线的章节，也可以让一个人物长期不出现，让某段关系暂时没有结论。

这种自主不要求系统提前为每个人模拟一条后台时间线。人物离开叙事以后仍被视为各自生活的中心；当他重新进入正文时，Agent 可以回读其历史，并创造此前未登记、却与其生活相容的新经历、关系和变化。新内容一旦写入正文，才成为作品历史。

### 6.7 未来可以被想象，但不必被保存

Agent 写作时可以同时想到几个可能的未来，也可以完全不这样做。未被采用的可能默认停留在当次思考或可回滚版本中，不自动沉淀为长期大纲、待回收伏笔或人物命运。

大纲记录的是作者曾经的打算。已经长成的人物、关系与局势共同指向别处时，Agent 可以直接偏航，并让正式章节成为新的依据。

### 6.8 写后检查以“不磨死正文”为边界

正文落盘后，Agent 可以检查遗漏前文、明显失真、解释过度和无意的模型套话，也可以局部重写。但它不应因为某段无法被概括、功能不清楚或没有推进情节就自动清理它。

自我审查的任务是发现明显的忘记与写假，不是把第一次写作中尚不能解释的东西整理得更像成品。

## 7. 怎样降低 AI 把人物写平的概率

这部分只能做负面防护，不能构成高级写作公式。

### 7.1 防止标签复读

若一段行动能够被人物卡中的一个形容词完整解释，Agent 应怀疑自己是否只在展示设定。

不是禁止人物表现稳定性，而是避免每次出场都用同一种方式证明稳定性。

### 7.2 防止情节代替人物

场景中的外部结果可以由大纲要求，但人物实现结果的具体方式不应提前写死。

如果换一个名字、换一份人物卡，场景仍然基本成立，说明人物没有真正参与事件生成。

### 7.3 防止过早解释

人物的行动可以比他的自我认识更深。模型不必立即让人物理解自己，也不必让旁白总结这一行为说明了什么。

解释不是永远禁止，而是不应自动尾随在每个复杂动作后面。

### 7.4 防止矛盾被清理

廉价模型很喜欢把冲突归纳成“其实他只是……”。这种句式常把一个人缩成单一动机。

多个互相冲突的动机可以同时成立，且人物本人未必知道比例。

### 7.5 防止回收过于整齐

旧情节再次参与现在，不等于复现旧动作、旧意象或旧台词。若回声过于工整，人物会像作者布置的机关。

更重要的是新行动能否让旧历史获得此前没有的意义。

### 7.6 防止“关键章自动升华”

死亡、告别、和解和背叛不自动要求庄重。人物可以以笨拙、可笑、自私、日常甚至不合时宜的方式面对它们。

场景的语气首先来自人物与关系，不来自事件类型。

## 8. 官网强模型接力：模型可替换，记忆不外包

### 8.1 官网模型是一次性的陌生写作者

作品记忆始终以本地文件为准。不能依赖官网 Project 或长会话记住全书，因为：

- 记忆不可验证；
- 上下文可能被平台压缩；
- 模型和产品会变化；
- 不同任务可能使用不同官网模型；
- 一旦对话失效，作品不应失忆。

官网长会话可以提供便利，但不能成为唯一记忆层。

### 8.2 本地 Agent 自行编译材料

不再固定“六张卡”或强制比例。Agent 根据任务决定提供：

- 当前任务和外部局面；
- 必要的世界事实；
- 它认为相关的人物与关系历史；
- 摘要、原文或二者混合；
- 当前软性大纲；
- 用户明确指出过的相关错误；
- 哪些内容仍未决定；
- 输出应写正文还是只做分析。

每项尽量带本地来源，便于回收后校验。

### 8.3 不提示“请写出灵性”

较好的任务表达是让官网模型面对具体局面与历史，并明确：

- 不必服从预设人物反应；
- 可以让人物行动改变后续计划；
- 不要用人物卡概括人物；
- 不需要升华、解释或完成主题；
- 如果材料不足，可以明确指出缺少哪段历史。

不要要求“意外但合理”“高级”“有灵魂”。这些词会把模型推向表演。

### 8.4 外部结果回收

用户粘回结果后，本地 Agent：

1. 保存原始外部回复和来源；
2. 判断哪些内容属于目标产物；
3. 自行决定是否需要补读本地历史进行校验；
4. 直接写入可回滚文件；
5. 更新客观事件、时间、人物所知信息和索引；
6. 需要时调整软性大纲；
7. 不让廉价模型对强模型正文做全面润色；
8. 不把外部模型的角色分析自动固化为人物真相。

强模型不只是润色器。某一章最关键的创作可以直接交给它完成；本地 Agent 负责准备历史、说明任务、保存原始回复，并把结果接回作品。

外部结果若局部很好、整体有误，本地 Agent 应优先保留真正成立的正文，只重写必要部分。廉价模型没有把强模型全文统一成自己语气的职责；用户也可以随时介入，决定哪些部分不应被它改动。

## 9. 用户指出“不对”时，系统真正应该学习什么

### 9.1 先诊断错误深度

```text
局部措辞不对
  -> 只修改局部

本场行动不属于这个人物
  -> 追溯相关历史，重写场景

关系语气已经偏离
  -> 检查近期共同场景与双方记忆

人物过去几章持续写偏
  -> 找到最早偏移点，提出或直接完成成组修订

大纲强迫人物
  -> 修改软性大纲，而不是继续修辞润色
```

Agent 自行判断从哪一级开始，并在高影响、无法合理判断时只问一个最小问题。

### 9.2 保存原话，不急着提炼规律

用户纠正最有价值的是当时的具体判断。保存：

- 用户原话；
- 指向的正文；
- 涉及人物与关系；
- 当时 revision；
- Agent 最终怎样修复；
- 用户是否继续指出问题。

未来是否召回、召回原话还是修订结果，由 Agent 决定。

### 9.3 几个字的修改不承担学习任务

微改可以修正文、事实和口吻，但没有修改动机，不能推出审美，更不能推出人物规律。

系统只保存 diff 与版本历史。除非用户明确说明原因，否则不额外解释。

---

## 10. 世界存在于有限叙事之外

“小说的迷人之处在于创造一个世界”，不等于生成庞大的设定百科，也不等于让每一个细节承担制度暗示或象征功能。

小说的视角和注意力是有限的。正文只能照亮世界的一小部分；世界的活，更多来自其中的人各自看见、记住、误解和忽略什么，以及他们没有被主角看见时仍是自己生活的中心。即使长期只有一个 POV，其他人也不应只是围绕这个 POV 运转的道具。

系统可以机械记录某个人在哪些章节出现、曾被哪些视角看见，方便 Agent 在人物重新进入叙事或获得新视角前回读原文。它不应据此建立 POV 排期、世界完整度指标或永久的内心档案。

制度、地理、资源与历史仍可在确有需要时保存事实，但系统不负责把世界模拟完整。没有写到的生活可以保持空白；人物重返正文时，可以带来过去从未登记、却使人相信他确实在别处生活过的变化。

同样，系统只需避免一种破坏：让人感觉作者忘了已经写过的前文。它不必把所有连续性变成类型和规则，更不应自动保存“这件事说明人物、世界或作品最终意味着什么”。

---

## 11. 廉价模型与 Token 优化

### 11.1 省 Token 的目标不是少读，而是不重复、不过早、不错读

固定限制模型只能读少量内容，会直接损害长篇生命。更好的优化是：

- 文件未变化时复用带 revision 的导航观察；
- 先看索引，再由 Agent 判断是否深入；
- 工具结果离开最近窗口后再 microcompact；
- session compaction 只保存当前任务连续性；
- 项目事实始终回到文件；
- 小修改只分析 diff 与必要邻近内容；
- 同一段原文在同一任务中避免重复读取；
- 记录真实 Token、缓存命中和官网材料体积。

### 11.2 稳定前缀优先

当前项目已经选择稳定 system prompt、按 Agent 角色固定工具 schema 和 append-only session，这有利于 Prompt Cache，也符合 Full Agent 思路。

不要为了每轮省一点工具 schema Token，把 Agent 的能力切成大量任务权限模式。可以让只读 checker 保持窄工具集，但主 Agent 应持续拥有完整工作能力。

### 11.3 软预算而不是内容配额

不同任务可以有默认成本预算，但预算应是软性的：

- 普通问答和局部修订快速完成；
- Agent 认为历史不足时可以说明理由并扩大检索；
- 关键写作可以升级官网强模型；
- 达到硬成本上限时停止并报告，而不是假装现有上下文足够。

当前按 workflow 固定 `maxLoops` 是合理起点，但可以演进为“默认循环预算 + 有新证据时延长 + 无新进展时提前停止”。

### 11.4 模型分工

| 层 | 适合做什么 |
| --- | --- |
| 确定性代码 | diff、revision、索引、路径、版本、Token、文件更新 |
| 廉价 API Agent | 检索判断、状态抽取、普通续写、局部修改、官网材料编译与回收 |
| 官网强模型 | 关键场景、人物关系突破、复杂改稿、长篇重新阅读与诊断 |

分工不是固定路由。Full Agent 可以根据当前任务和失败情况升级。

---

## 12. 最小数据落点

不建设需要用户维护的复杂数据库。建议只区分三类：

```text
作品本体
  章节正文/
  大纲与设定文件
  用户明确写入的项目规则

可重建导航
  .novel-guide/index/
    章节事件、人物出现、共同场景、来源指针、revision
  .novel-guide/cache/
    文件观察、搜索结果、临时分析

明确纠正与运行历史
  .novel-guide/corrections.jsonl
  ledger / revisions
  inbox/external/
```

`corrections.jsonl` 保存用户原话，不保存系统推测出的审美画像。

导航文件可以用 JSONL 或 SQLite，但正文、设定和大纲继续保持人类可读。用户无需打开 `.novel-guide` 才能正常创作。

## 13. 对当前实现的判断

当前工作区已经出现了一些正确变化：

- `DEFAULT_SYSTEM_PROMPT` 已明确完整读写、可回滚直接行动，以及“不可替代的生命感”优先；
- `permissionMode: "bypass"` 已进入 LG Agent 默认运行；
- User Memory 相关路由、组件和存储正在删除，符合“不从行为建立用户画像”；
- compaction 设计已明确项目事实以文件为准，只服务当前 session；
- system prompt 与主 Agent 工具 schema 强调稳定前缀；
- workflow 已有不同循环预算；
- `/eject` 已覆盖中文内容目录并记录 Token；
- 子 Agent 定义已经解析 `tools/model/maxLoops`。

仍值得继续调整：

1. 文档中残留的 Context Compiler 应改成 Agent 可自主使用的导航能力，而不是固定组包器。
2. `continue/revise` 仍有较强 workflow 目标与默认目录，应确保它们不限制 Agent 修改必要的软性大纲和相关历史。
3. 固定 `taskLoopBudget()` 可升级为软预算与无进展停止。
4. `/handoff` 与 `/eject` 应允许 Agent 自行选择摘要、原文和文件，而不只依赖固定卡片或显式路径。
5. `chapter-delta` 适合自动更新客观状态，但不要从事件抽取人物本质。
6. review checker 只能检查连续性、明显失真与具体失败，不能充当文学价值裁判。
7. 用户明确指出的人物/关系错误需要本地、跨线程、带来源地保存。

## 14. 评估什么

不评估灵性，不计算“人物真实度”，也不让 LLM 给文学价值打分。

可以评估系统是否妨碍或帮助了创作：

### 14.1 Agent 与成本

- 完成一次任务的调用数、Token 和现金成本；
- 重复读取同一 revision 的比例；
- Agent 追加检索后是否获得了新证据；
- 无新进展循环数；
- 官网材料中真正被结果使用的内容；
- 外部结果回收成功率。

### 14.2 长篇记忆

- 用户指出“忘了以前发生过什么”的次数；
- 来源指针是否能回到真实原文；
- 摘要与当前正文冲突的比例；
- 人物双方认知是否被错误合并；
- 未决定内容是否被模型擅自写成事实。

### 14.3 用户纠正

- 同一人物、同一关系的明确错误是否反复出现；
- 收到“不对”后，Agent 能否找到真正偏移层级；
- 修订是否只改了措辞，却保留了错误行动；
- 用户需要花在解释系统和维护文件上的操作是否下降。

“用户继续阅读”只能说明产品仍可用，不能说明这一段有灵性；“用户没改”也不能说明用户满意。

## 15. 推荐实施顺序

### 阶段 0：删除错误抽象

- 从设计文档中删除 Spirit Engine、火种、审美学习和灵性 KPI；
- 固定正文为人物与关系的最终来源；
- 明确派生人物解释可被 Agent 怀疑和丢弃；
- 保持 Full Agent 与可回滚直接执行。

### 阶段 1：本地导航记忆

- 建立 revision-aware 章节与场景索引；
- 支持按人物、关系、物件、旧话和事件追到原文；
- 摘要只作导航，全部带来源；
- 小修改增量更新，不重扫全书；
- 删除索引后能够从作品文件重建。

### 阶段 2：Agent 自主追溯

- 给主 Agent 显示 Token、成本和当前证据覆盖；
- 允许它自行在摘要、片段和完整章节之间深入；
- 将固定循环上限改为软预算与无进展停止；
- 写作前不自动注入人物答案，只提供 Agent 选择的历史。

### 阶段 3：官网模型无状态接力

- 本地 Agent 自主决定每次材料；
- 外部包携带来源与本地 revision；
- 官网输出保存原文后再由本地 Agent 吸收；
- 不依赖官网对话维持作品记忆；
- 不让廉价模型全面润色强模型正文。

### 阶段 4：纠正与偏移诊断

- 保存用户明确纠正及其作用对象；
- 判断局部错误、场景错误、关系漂移和多章偏移；
- 必要时修改软性大纲，而不是强迫人物；
- 不把项目纠正提升为用户审美画像。

### 阶段 5：持续观察真实写作

- 用真实长篇检验索引是否找得到遥远旧场景；
- 观察人物何时开始复读标签；
- 记录用户指出“不对”的真实原因；
- 改进 Agent 的追溯和判断提示，但不提炼人物生成公式。

---

## 16. 明确不建议做的事

1. 不做权限模式；Agent 在作品工作区内始终 full。
2. 不让用户维护人物数据库、关系数值和灵性标记。
3. 不把微改、未修改或保留行为解释成审美。
4. 不建设灵性评分器、人物真实度分数或高级感 critic。
5. 不把人物压成唯一人物卡，不用新摘要覆盖旧矛盾。
6. 不规定每个关键场景必须生成多个候选。
7. 不要求每章出现意外、深度或人物突破。
8. 不把“事前不可算、事后有根”用作生成模板。
9. 不让大纲拥有高于已经长成的人物与关系的权力。
10. 不依赖官网模型保存项目记忆。
11. 不为了省 Token 固定禁止 Agent 深读历史。
12. 不把模型对人物的解释自动写成作品事实。
13. 不建立读者知识、读者感受或作品意义状态机。
14. 不要求每个细节都承担暗示、象征或世界说明功能。

---

## 17. 最终产品想象

LG 不需要假装自己掌握了灵性算法。

它更像一个拥有完整工作权限、长期住在作品本地文件中的创作 Agent：

- 它记得事实，也知道自己的摘要可能错；
- 它可以先看索引，也可以在必要时重读几十章以前的原文；
- 它不把人物卡当人物；
- 它允许两个人对共同历史拥有不同记忆；
- 它不急着解释普通细节将来有什么用；
- 它让人物的行动修改大纲，而不是让大纲借人物的嘴完成任务；
- 它把官网强模型当作可替换的写作者，把作品记忆牢牢留在本地；
- 它允许未来只在创作当下短暂出现，不把每个可能都变成计划；
- 它知道叙事注意力有限，不试图模拟完整世界或预先管理读者理解；
- 用户只需阅读，并在真正不对时指出哪里不对。

随着小说变长，系统增加的不应是一套越来越严密的人物规律，而是一段越来越丰厚、仍然没有被解释完的历史。

有一天，人物在一个具体处境中做出读者事前想不到的事情。它没有违背过去，反而让过去第一次以新的方式同时成立。读者未必因此更懂这个人，却更无法否认这个人确实存在。

产品不能制造这一刻。

它真正能做的，是让此前几百章没有在摘要、套路、大纲和成本优化中被提前耗尽。
